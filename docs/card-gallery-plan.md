# CyberTarot 卡片画廊改造方案

## 改造目标

将首页改成免登录的卡片画廊。用户打开网站即可看到第一张牌，在手机上左右滑动，或在桌面上使用触控板和翻页按钮，依次浏览全部 78 张牌。画廊直接读取项目内的牌面图片和中英文牌名，移除提问、洗牌、抽牌、AI 解读及密钥验证流程。

## 一、实现卡片画廊

新增 `src/components/CardGallery.tsx`，作为负责滚动和翻页的客户端组件。

- **数据与顺序**　从 [卡片数据](../src/data/cards.ts) 读取 `CARDS`。沿用现有的大阿卡纳、权杖、圣杯、宝剑、星币顺序，通过 `imagePath` 加载牌面，以 `nameZh` 和 `nameEn` 显示牌名。
- **滑动与吸附**　使用横向滚动容器，设置 `display: flex`、`overflow-x: auto` 和 `scroll-snap-type: x mandatory`。每个卡片项设置 `flex: 0 0 100%` 和 `scroll-snap-align: center`，让松手后的牌面停在视口中央。
- **牌面布局**　让图片在可用宽高内按比例缩放，设置 `object-fit: contain`，并为牌名、页码和按钮预留空间。优先加载首张牌，其余图片按需加载。
- **翻页与计数**　在画廊底部显示“上一张”“下一张”和当前位置。按钮滚动到相邻卡片，页码根据实际滚动位置更新，总数取 `CARDS.length`。到达首张时禁用“上一张”，到达末张时禁用“下一张”。

## 二、替换页面入口

| 文件 | 改动 |
| --- | --- |
| [首页](../src/app/page.tsx) | 将首页内容替换为 `CardGallery`，直接显示第一张牌。 |
| [全局布局](../src/app/layout.tsx) | 移除 `TarotProvider`，将页面标题、描述和社交分享文案更新为卡片画廊介绍。 |
| [原牌库页](../src/app/cards/page.tsx) | 将 `/cards` 重定向到 `/`，使已有书签继续可用。 |
| [关于页](../src/app/about/page.tsx) | 将 `/about` 重定向到 `/`，统一进入画廊。 |

## 三、清理旧功能

1. 首页切换后，移除前端对 [解读接口](../src/app/api/reading/route.ts) 和 [密钥验证接口](../src/app/api/verify-key/route.ts) 的调用，再删除这两个路由。
2. 检查占卜状态管理、抽牌逻辑、AI 客户端及旧界面组件的引用，删除已无调用的代码。保留画廊使用的卡片数据、类型和图片。
3. 更新 [项目说明](../README.md) 中的功能介绍和启动步骤，移除旧流程所需的密钥配置说明。将 [牌库页面测试](../__tests__/app/cards.test.tsx) 中针对筛选和详情弹窗的用例替换为画廊与入口跳转的测试。

## 验收清单

- [ ] 在未登录、未配置 AI 密钥的情况下打开首页，直接看到「愚人 / The Fool」和 `1 / 78`。
- [ ] 手机竖屏可左右滑动，每次停止后牌面居中，插画边缘完整可见。
- [ ] 触控板滑动和按钮翻页可交替使用，页码和牌名始终对应当前牌面。
- [ ] 全部 78 张牌均能正常显示；首张和末张的对应边界按钮已禁用。
- [ ] 直接访问 `/cards` 或 `/about` 均能进入首页画廊。
- [ ] 浏览期间无解读或密钥验证请求，旧接口已下线，项目可正常构建。
