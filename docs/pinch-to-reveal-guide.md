# 电脑端捏合翻牌实现指南

左右挥手负责选牌，拇指和食指轻捏负责确认。牌环停稳后，捏住约 **250 毫秒**，正前方的牌背亮起描边并打开对应大图。松开两指，再捏一次，返回同一张牌所在的牌环。沿用现有摄像头和手部模型，单次翻页、停留连翻两种模式均可使用。

## 1. 用指尖距离识别一次捏合

建议在 `src/lib/pinch.ts` 新增一个只处理视频帧数据的判定器。在现有识别循环中，同一帧的手部关键点同时可用于计算掌心和捏合距离。取拇指尖（4）、食指尖（8）、食指根（5）和小指根（17），按以下方式计算比例。坐标先换算为像素，避免摄像头画幅比例影响距离。

```ts
const distance = (a: Point, b: Point) =>
  Math.hypot((a.x - b.x) * videoWidth, (a.y - b.y) * videoHeight)

const palmWidth = distance(points[5], points[17])
const ratio = distance(points[4], points[8]) / palmWidth
```

四个点缺失、掌宽过小或比例无效时，取消本次识别。以下数值供首轮真机校准：

当前实现将小于 12 像素的掌宽视为无效；捏合中掌心相对起点的横向或纵向移动超过画面对应方向的 5% 时撤销确认。每次选牌输入都会更新目标版本，即使用键盘切走后又切回同一张，也不会确认旧的捏合。

| 阶段 | 判定与动作 |
| --- | --- |
| 等待张开 | 先观察到 `ratio ≥ 0.45`，才允许开始。用户捏着手入镜时，提示「先松开两指」。 |
| 开始捏合 | `ratio ≤ 0.25` 时记录当前帧时间、掌心位置和目标牌位，开始点亮描边。 |
| 持续确认 | 手保持稳定且尚未张开，按新视频帧的时间累计。达到 250 毫秒时触发一次确认；提前张开或目标变动则取消。两个阈值之间沿用上一状态，减少边界抖动。 |
| 等待释放 | 确认后锁定，看到两指重新张开才解锁。这个锁跨越牌环和大图的切换，避免一次长捏同时触发打开和返回。 |

## 2. 协调挥手、连翻和捏合

在 [useHandSwipe.ts](../src/hooks/useHandSwipe.ts) 的现有视频帧循环中增加捏合判定，向画廊提供确认回调和捏合进度。每个新视频帧最多派发一个动作。

- **允许开始的时机**：已有 [HandSwipeTracker](../src/lib/handSwipe.ts) 报告 `ready`，当前掌心仍在居中区，且画廊已停稳。桌面拖动、滚轮输入、吸附动画、侧边等待连翻或正在连翻期间均不开始计时。连翻后沿用现有回中停稳流程。
- **区分捏合和横移**：每帧先检查挥手结果。已产生翻页事件时取消捏合，只派发翻页。捏合期间若掌心相对起点明显横移（可先试画宽的 5%），立即撤销描边，让原有挥手识别继续跟踪。这样用户改变主意去选下一张时，也不会翻开旧牌。
- **中断处理**：丢手、帧间隔超过跟踪宽限、目标牌位变化、手势模式切换或页面隐藏时清空计时。恢复后重新观察两指张开。关闭摄像头或组件卸载时，随现有会话一起清理。

## 3. 接入画廊反馈

在 [CardGallery.tsx](../src/components/CardGallery.tsx) 中复用 `changeMode`。确认时若处于 `ring`，调用 `changeMode("detail")`；若处于 `detail`，调用 `changeMode("ring")`。触发前复核视图、牌位与开始捏合时一致，保留现有点击、Enter 和 Esc 操作。

牌环就绪时提示「左右挥手选牌，拇指与食指轻捏翻开」。将进度传给 [CardRing.tsx](../src/components/CardRing.tsx)，只点亮正前方牌背的描边。大图中将同样的反馈放在「返回牌环」按钮上，提示「再次轻捏，返回牌环」。松开前显示「松开两指」，读屏提示只播报阶段变化。

## 验收

- **一次长捏只切换一次。** 用模拟帧验证未满 250 毫秒不触发、到期触发一次、继续保持不重复、松开再捏才返回。
- **连翻与捏合互不误触。** 停在侧边捏手时只执行原有连翻；收手回中、牌环停稳，再捏合应打开当前牌。识别中途横移、丢手或用键盘换牌，都应撤销确认。
- **真机检查。** 在平时使用电脑的距离试左右手和不同手掌角度，检查轻捏时描边是否可见、打开后是否容易松手返回，再调整比例阈值和确认时长。
